# 电脑控制（Computer Use）

自建版 ZCode 的 Computer Use 能力。当用户要求操作电脑桌面（而不只是浏览器）时，使用本技能。

## 前提

- 依赖 MCP server：`open-computer-use`（已在工作区 `.mcp.json` 预置）。
- Windows 无需额外权限授予；macOS 需要先授予"辅助功能 + 屏幕录制"权限。
- 如果 `mcp__open-computer-use__*` 工具不可用，说明 MCP server 未连接，先检查配置再继续。

## 工具面

通过 MCP 工具 `mcp__open-computer-use__*` 调用，常用工具：

| 工具                       | 用途                                                          |
| -------------------------- | ------------------------------------------------------------- |
| `list_apps`                | 列出当前运行/最近使用的应用                                   |
| `get_app_state`            | 读取目标应用界面（截图 + 无障碍树），**每轮交互前必须先调用** |
| `click`                    | 点击元素（可指定元素索引或坐标）                              |
| `type_text`                | 输入文本                                                      |
| `press_key`                | 按键或组合键                                                  |
| `scroll`                   | 滚动页面                                                      |
| `drag`                     | 拖拽                                                          |
| `set_value`                | 设置可编辑元素的值                                            |
| `perform_secondary_action` | 触发元素次要操作                                              |

## 工作流程

1. **找目标应用**：先调用 `list_apps`，从结果中确定目标应用名（应用名是后续工具的 `app` 参数）。
2. **读取界面**：调用 `get_app_state`，传入目标应用名（如 `{ "app": "chrome" }`），获取截图和界面树；根据界面树确定元素索引或坐标。
3. **执行操作**：按用户意图调用 `click` / `type_text` / `press_key` / `scroll` 等，**必须传入 `app` 参数**。
4. **确认结果**：操作后再次调用 `get_app_state` 观察界面变化，确认操作生效；需要时把截图/状态通过 `nodeRepl` 或文本方式反馈给用户。

## 注意事项

- 所有操作工具都要求 `app` 参数（应用名或应用标识），取自 `list_apps` 结果。
- 坐标基于最近一次 `get_app_state` 返回的截图像素坐标。
- 这些是**真实系统级操作**，会实际影响用户桌面；执行点击/输入前先确认目标窗口和元素正确，避免误操作。
- 读取界面后不要立刻重复调用 `get_app_state`；只有在执行了操作之后才需要重新读取。
- 如果用户说"打开 XX 应用"，先用 `list_apps` 确认它是否在运行；未运行时提示用户手动打开（当前版本 `open_application` 不可用）。
